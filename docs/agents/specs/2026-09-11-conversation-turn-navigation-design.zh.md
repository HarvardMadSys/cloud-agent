# Cloud Agent 对话导航条

状态：已实现（Web Chat 前端）。真实浏览器下的滚动几何、100 轮以上的历史和 staging 验收仍待人工确认，步骤见 [Conversation view](../../developer/web-app.md#checking-it-in-a-browser)。使用者视角的行为说明见 [Conversation view](../../developer/web-app.md#conversation-view)。

设计参考 deepseek-harness 的 `TurnNavigator` 交互：固定间距刻度、悬停预览、内部滚动、交互时暂停自动跟随。

## 要解决的问题与决定

一段对话包含多次提问、回复、工具执行和运行状态，历史越长越难找到"我之前问的那个问题"。Chat 右侧有一列按对话轮次排列的横线，悬停预览，点击定位，并显示当前阅读到哪一轮。

首版完全在前端实现：复用 Chat 已读取的 job、thread 和事件数据，不需要新 API、数据库迁移或 runner 改动。

| 决策 | 行为 |
| --- | --- |
| 导航单位 | 一轮用户请求及其 agent 活动，即一个 job。多个 attempt 共用一个刻度 |
| 导航范围 | 当前 Chat 实际展示的轮次（会话前缀） |
| 预览 | 该轮首条用户输入，加已结束轮次的最后一段可见回复。从已有文本截取，不调用模型 |
| 点击 | 在当前 Chat 内滚到该轮开头，不切换路由、attempt、工作区或执行状态 |
| 当前刻度 | 由阅读位置算出，与当前运行中的轮次分开 |
| 流式输出 | 读者在看历史时保持位置，只有主动回到底部或提交新一轮才恢复跟随 |
| 长对话 | 刻度间距固定，导航条自身滚动，不把刻度压缩到不可点 |

不改变 HybridInference gateway、原生会话恢复、Fork、Edit & rewind 或 Trajectory 视图的语义。

## 用户体验

导航条在 Chat 阅读区右侧的留白内。打开 Git、Terminal、Files 后它仍属于 Chat 列，不跟着浏览器右缘移动。预览卡向左展开，不遮住输入框、页头或工作区分隔条。

1. 只有一个可导航轮次时隐藏。至少两轮且空间允许时显示右侧横线。没有顶部"Turns"按钮或目录弹层，窄屏也没有。
2. 普通刻度是短横线，当前阅读轮次更长更亮，悬停或聚焦的有独立反馈。长度只表达交互状态，不表示消息长度、耗时或进度。
3. 悬停只显示问题和可用的回复预览，不显示轮号或状态。悬停不滚动、不请求网络、不改变当前轮次。指针移入预览卡后保持显示，离开导航条和卡片或按 Escape 关闭。
4. 点击刻度，把该轮第一个用户输入定位到阅读区顶部下方约 24px。没有用户文本时，定位到该轮首个可见内容或占位行。
5. 点击最新一轮仍定位到这一轮的开头。"回到底部"定位到正文末尾，用途不同。
6. 读者在看历史时，正文右下方出现 36px 的圆形向下 chevron，与输入区右缘对齐，距输入区 16px。有新内容时加小圆点，文字放在 tooltip 和无障碍名称里。
7. 导航条溢出时内部滚动，上下渐隐提示还有轮次。指针或键盘焦点在导航条内时不自动移动它，离开后再让当前刻度可见。导航条滚动不带动正文。
8. 排队、运行中、失败、已停止的状态只出现在读屏描述里，横线配色统一。状态未知时省略，不推断成败。

聊天正文没有 "Turn N" 分隔标签，跳转成功只向读屏播报。

| 项目 | 值 |
| --- | --- |
| 导航列宽 | 32px，正文为它留至少 40px |
| 横线 | 普通 12×2px，悬停 18×2px，当前 20×2px |
| 刻度间距 | 固定 24px，每项命中区至少 32×24px |
| 最大高度 | `min(420px, 有效阅读高度 − 64px)` |
| 预览卡 | 最大宽 280px，问题 1 行，回复最多 3 行 |
| 显示条件 | Chat 列宽至少 720px、有效阅读高度至少 200px、精细指针设备 |

判断宽度用 Chat 容器宽度。浏览器很宽但工作区占去大半时，空间不足就隐藏横线，正文仍可正常滚动。触屏和窄屏沿用正文滚动。

## "一轮"的数据语义

目录以 Chat 当前的分组结果为准，按 `turnNo` 排序，以 jobId 去重和定位。工具调用、reasoning、usage、lifecycle 和单条 assistant 消息都不单独产生刻度。

页面按选中的 job 展示会话前缀（之前的轮次加当前轮次）。从旧 job 链接打开第 4 轮时，目录只含第 1–4 轮，即使 thread API 还返回了之后的 job，不显示找不到正文的刻度。

| 情况 | 处理 |
| --- | --- |
| 当前 prompt 也在 durable messages 里 | 遵守 `historyIncludesPrompt`，正文和目录各一份 |
| 一个 job 有多个 attempt | 一个刻度，切换 attempt 不增加轮次、不重置阅读轮次 |
| 当前轮已排队，之前一轮仍在运行 | 两轮分别存在，状态读实际 job 元数据 |
| Fork 复制出的历史没有 events | 用该子会话已复制的 jobs/messages，锚点用新的 jobId |
| 有 job 但没有消息 | 保留占位行和可导航锚点，预览显示"暂无消息文本" |
| 旧 standalone job | 单轮，导航隐藏 |
| 缺 `historyTurns` 的旧数据 | 按 `threadMessages.jobId` 归组，缺轮号时用显示序号 |

内部视图类型（不是后端响应）：

```ts
interface ConversationTurnNavigationEntry {
  key: string;            // 会话内的 jobId，稳定身份
  jobId: string;
  turnNo: number;         // API 轮号；旧数据才用显示序号
  promptPreview: string;
  responsePreview: string; // 未结束或无可见回复时为 ""
  state?: AgentJobState;   // 复用已有映射，缺失时不推断
  previewAttemptNo?: number;
}
```

DOM 元素放在控制器的 `Map<key, HTMLElement>` 里，不进数据模型。`turnNo` 用于排序和读屏，不能跨会话当身份。事件 `seq` 是 attempt 内序号，不能当全会话唯一键。

为避免正文和目录各写一套规则，从 `JobDetail` 里提取了一个轻量的轮次描述层，决定哪些消息渲染、轮次顺序、首个锚点和最后一条可见回复。显示序号只是兼容逻辑，不写回 `turn_no`，也不用于原生 Fork 定位。

### 预览规则

- 问题：优先用正文里该轮的首个用户输入，正文用 job prompt 时就用 prompt。不用会话标题。
- 回复：轮次进入终态后，取正文最后一条非空 `message`；正文回退到 durable assistant messages 时从同一集合选。失败或停止时可显示已产生的最后一段文本，状态由读屏描述提供。当前轮选了历史 attempt 时，回复预览遵循该 attempt，并在读屏描述里标明。
- 没有明确终态时 `responsePreview=""`。不能用 `forkable` 判断结束，它还包含 Fork 能力等条件。
- 预览是转义后的纯文本，合并空白，问题最多 50 字符、回复最多 120 字符，截断加省略号，不切断 Unicode 字符簇。截断惰性读取字符簇，读满预算就停，所以成本与回复长度无关。
- 不从工具参数、工具输出、原始 thinking、隐藏上下文或运行日志取预览，只用当前用户已可见的 Chat 文本。
- 流式期间不逐事件刷新回复预览，终态后更新一次。

## 组件与数据流

| 单元 | 位置（`apps/frontend/src/components/features/agents/`） | 职责 |
| --- | --- | --- |
| `conversationTurnNavigation.ts` | `conversation/` | 共享轮次描述和目录派生：去重、兼容回退、限长预览，不读写 DOM |
| `TurnNavigator.tsx` | `conversation/` | 刻度、预览、内部滚动、回到底部。只接收条目、activeKey 和回调 |
| `useConversationScroll.ts` | `conversation/` | 注册锚点、计算当前轮次、跳转、底部跟随、布局补偿，统一拥有正文滚动写入 |
| `JobDetail.tsx` | | 接线和锚点 |

展示行带稳定的 `AgentEvent.sourceEventId`（`types.ts`、`adapt/`），用于阅读锚点，不返回给模型也不改后端事件。文案在 `lib/i18n/dictionaries/{en,zh-CN}.ts` 的 `turnNavigation.*`。

控制器提供 `jumpToTurn(key)` 和 `returnToBottom()`。导航 UI 不直接调用 `window.scrollTo()`、Next router 或 job 操作 API。导航框放在滚动区域外的相邻绝对定位层里，由包住 `Task progress` 的相对定位容器承载，不增加正文 `scrollHeight`。层级从下到上：正文、导航预览、输入框与页头、模态窗口。

## 滚动与定位

### 位置与跟随意图

`atBottom` 是几何位置，`mode` 决定下一次内容变化后的滚动，两者不是同一个布尔值。

| 模式 | 进入条件 | 新内容或布局变化后 |
| --- | --- | --- |
| `following` | 首次打开且没有阅读位置；点"回到底部"；本人新一轮提交成功并已显示；用户主动滚到末尾 | 跟随正文末尾，当前刻度为最后一轮 |
| `reading` | 用户向上阅读；跳转完成；切到历史 attempt | 保留阅读锚点，新回复或终态刷新不自动滚到底 |
| `jumping` | 点击刻度 | 暂停跟随，定位目标，布局提交后进入 `reading` |

点击最新刻度后，即使因内容较短而恰好在底部，也保持 `reading`，恢复跟随需要新的明确动作。新一轮提交失败时保留原位置和草稿，不提前进入 `following`。

用户滚轮、触摸、阅读区里的滚动键或拖动滚动条要立即取消待执行的跳转和跟随，不等延迟的 `scroll` 采样。浏览器因布局调整产生的滚动不能被当成用户主动回到底部：控制器自己真正改变位置的写入会标记，其引发的首个 scroll 事件不参与手势判定，任何用户手势会清除该标记。

### 当前阅读轮次

1. 从 `Task progress` 的可见区域扣除 sticky 输入区实际遮住的底部，得到有效阅读高度 `H`。
2. 阅读线在 `container.top + min(96px, 0.2 × H)`。
3. 非跟随状态下，选开头不晚于阅读线的最后一轮；阅读线还没到第一轮时选第一轮。这样一轮很长、提问已滚出屏幕时仍能正确高亮。
4. 正文在底部时直接选最后一轮，覆盖短内容无法顶齐的情况。这个几何判断本身不把 `reading` 改成 `following`。

位置缓存只在条目结构、Chat 宽度、正文高度或输入区遮挡变化时失效。`requestAnimationFrame` 合并同一帧的测量，先读几何再写滚动位置。

### 点击跳转

点击后：取消旧导航意图，退出跟随，查找目标 DOM，在真实滚动容器内定位，布局提交后重新测量，更新 activeKey。

```text
targetTop = 当前 scrollTop + 目标锚点.top − 滚动容器.top − 24px
最终位置 = clamp(targetTop, 0, 最大 scrollTop)
```

跳转直接定位，不做动画，避免长对话持续输出时目标漂移。用户手动滚动、再次点击、切换会话或视图都会取消旧跳转，导航意图带递增 generation，旧回调不能把用户带回前一个目标。目标当前不存在时保留阅读位置并提示"该轮内容暂不可定位"，不反复重试，也不静默跳到别的轮次。

### 布局变化与同会话续聊

用 `ResizeObserver` 观察正文、滚动容器和输入区。输出追加、工具展开收起、Markdown 渲染完成、打开工作区导致的重排都走同一个处理流程。

- `following`：布局更新后跟随新底部。变化前不在底部时，把落点当作阅读位置并转入 `reading`，判断用变化前的 `clientHeight`。
- `reading`：保存阅读线附近稳定内容块及其视口偏移，变化后恢复。尾部新内容不改变阅读位置。
- 内容块身份优先用 durable message id 或全局 event id（前缀 jobId），工具结果合并进工具行后保留原工具行身份，不用数组下标。
- 锚点因 attempt 切换或折叠消失时，退回同一轮的开头，同一轮也没了就选范围内最近的轮次。不能因此误触发底部跟随。
- 同一 `conversationKey`（`threadId ?? job.id`）增加 follow-up 时保留已有历史 DOM 身份和阅读状态，只有本人提交成功才触发底部跟随。读者主动选的、且不是最新的 attempt 才会让控制器保持 `reading`，排队轮次自动产生首个 attempt 不算。
- 切换会话时清理 observer、缓存、预览、锚点和待定位回调。切 Chat/Trajectory 时保存阅读锚点，隐藏导航并暂停 observer，回来后恢复。
- 阅读状态只在页面内存里，整页刷新按首次打开处理。可分享的轮次 URL 是后续需求。

## 可访问性与内容边界

- 导航是有名称的 `<nav>` 加真实按钮。按钮标签"跳转到第 N 轮"，当前项用 `aria-current`，焦点预览通过 `aria-describedby` 关联。方向键切换焦点，Home/End 到首尾，Enter/Space 定位，方向键本身不滚动正文。用 roving tabindex，Tab 不用遍历几百个刻度。
- 键盘定位后焦点留在导航上，允许连续跳转，用简短的 `aria-live="polite"` 确认目标，只在显式定位时播报。Escape 关闭预览，并由 document 级监听接管，避免冒泡到页面级的"Esc 停止运行"。输入框里的方向键、Home/End 和输入法由输入框处理，不注册全局快捷键。
- 滚动容器在 tab 顺序里，纯键盘可直接翻正文。
- 要在浅色、深色、键盘 focus 和 `prefers-reduced-motion` 下都可用，减少动态效果时禁用刻度和预览动画。
- 预览与正文使用同一份已授权的数据。导航不打开新订阅，不在本地持久化预览，不写入日志或遥测，纯文本按 React 默认方式转义。权限撤销或会话删除使正文失效时，导航和预览一并卸载。

## 性能

目录随轮次数增长，每轮只存限长预览和标识。刻度列表的引用稳定由 `sameNavigationEntries` 保证：把新派生的条目与上一批逐字段比较，相同则沿用旧数组，所以每个 SSE token 不会重建几百个刻度。不用摘要式缓存，因为它要预判刻度依赖的每个字段，漏一个就会长期提供旧刻度。历史轮次及其条目按 `historyTurnsDigest` 记忆化，只有当前轮次按 `navigationEntryDigest` 重算。

悬停和点击不发请求。初始 Chat 仍加载完整事件，导航不降低首屏网络量，也不解决完整 transcript 的内存问题。

## 后续：历史分页

等将来让 Chat 首屏只加载最近若干轮时，再单独设计服务端目录和按轮读取（deepseek-harness 的做法是服务端按持久化事件生成完整轮次目录），目前没有这个接口。要满足：

1. 轻量目录覆盖可浏览范围内的全部轮次，包括未加载、无事件、Fork 复制和仅有 prompt 的轮次，用现有 jobs/messages 提供目录身份。
2. 稳定地址用 thread/job 身份，需要事件定位时用全局 event id，不能把 attempt 内 `seq` 当跨轮次游标。
3. 目标轮次加载、挂载、再定位的过程要有界。目前只有 `after` 的正向事件分页，不足以直达历史轮次，不能靠从 0 重拉全日志假装按需导航。
4. 显示加载中、失败重试和无法读取的提示，新点击、用户滚动、会话切换使旧加载失去落点权限。
5. 目录与内容使用相同的 owner 检查，正文窗口替换或前插时保留阅读锚点。

## 验收场景

| 场景 | 通过条件 |
| --- | --- |
| 单轮与多轮 | 单轮隐藏。每个展示的 job 恰好一个刻度，顺序与正文一致 |
| 长回复、多工具、重试 | 仍只有一个刻度，切换 attempt 不改变目录身份 |
| 预览来源 | 多条 assistant 消息取最后一条；Fork 无 events 取 durable messages；不显示 thinking 或工具输出 |
| 未结束与异常轮次 | 排队或运行中只预览问题；停止或失败保留已产生的文本；无文本时保留可定位锚点 |
| 当前 prompt 去重 | 不产生重复正文、刻度或 DOM id |
| 历史 job 链接 | 目录只到当前页面展示的轮次 |
| 普通点击 | 目标锚点距容器顶约 24px，误差不超过 4px，受首尾边界限制时允许 clamp |
| 单轮很长 | 提问已离屏、仍在读该轮回复时，当前刻度仍指向该轮 |
| 流式输出时读历史 | 已有阅读块保持屏幕位置，误差不超过 4px，不被拉到底部 |
| 工具、输入区、工作区重排 | 按模式保持位置，锚点消失则按上文回退 |
| 同会话续聊 | 旧轮次身份稳定。本人发送成功则跟随新轮，失败则保留原阅读位置 |
| 连续交互 | 快速点第 2、8、3 轮只落在最后目标。用户滚动取消待跳转，切换会话不被旧回调拉回 |
| 返回最新内容 | 点最新刻度到该轮开头，"回到底部"到正文末尾并恢复跟随 |
| 超长导航 | 200 轮仍固定间距、内部滚动、边缘提示，全部可通过横线或键盘访问 |
| 无副作用 | 不调用 Follow-up、Fork、Rewind、取消或工作区 API，不改 URL、attempt 选择和输入草稿 |
| 生命周期 | 数据失效或身份切换后预览清空，卸载时 observer、监听、RAF 和待定位意图全部清理 |

纯数据规则用 Vitest 验证，组件交互用 React Testing Library。滚动几何、sticky、ResizeObserver、指针和浏览器布局必须在真实浏览器验证，jsdom 不够。仓库目前没有配置 Web 浏览器 E2E 入口，所以用可复现的人工步骤验收（见上方链接）。
