# 记忆功能设计

状态：核心已实现：`agent_memories` 表、Agent 的 memory 工具、写入时整理、归档与恢复、设置页、首轮和变化时注入、独立的 `GET /v1/agent/insights`。尚未实现：对话里的"已记住 · 撤销"提示和"用了 N 条记忆"标签、消息旁的"记住这条"、用户级指令文件交付、条数多时只发索引。

## 目标

记忆只做一件事：保存 Agent 应长期遵守的规则，让用户看得见、改得了。

- 长期保存，直到用户修改、删除或删掉来源对话。
- 任何语言都能记。Agent 记下的记忆统一用英文存。
- 用户无感：自动记录、直接生效，不弹确认、不打断任务。用户随时能看、改、撤销。
- 重复和冲突在写入时处理，不需要手动整合。
- 用户记忆与每个仓库的项目记忆各自独立，冲突时项目记忆优先。

不做：记录代码库知识（应写进仓库的 `AGENTS.md`）；跨用户的团队记忆；向量库或图数据库；画像、关注领域、"任务背景"这类近期动态。头像主题、默认头像和首页改进建议不属于记忆，由 `GET /v1/agent/insights` 在每次读取时从最近 50 条请求计算，不存表，也不受记忆开关控制。

## 为什么不用现成的记忆系统

每人、每仓库只有几十条规则，数据必须留在自己的 Postgres 里并按用户隔离，接外部服务得不偿失。设计只借鉴几个做法：

- 像 Claude Code 的自动记忆：由 Agent 自己决定记什么，不让用户确认，一条一个单元，带一句话描述。
- 像 Mem0：写入时决定新增、更新、删除还是忽略，不靠手动整合。这里由 Agent 自己选，因为它在会话开始时已看到同范围的全部记忆。
- 像 Graphiti：被替代的旧记忆归档，不直接删除，可查看和恢复。

不用向量检索（量太小）和知识图谱（对几十条规则过度）。现成的记忆 MCP 服务器也不直接用：官方 `server-memory` 把所有人的记忆写进同一个本地文件，没有用户和仓库隔离；Mem0/OpenMemory 的用户身份由调用方自报，而调用方是沙箱里不可信的 Agent。

## 数据模型

每条记忆是 `agent_memories` 的一行。`repo` 为空是用户记忆，有值是该仓库的项目记忆。

| 列 | 说明 |
| --- | --- |
| `id`、`user_id`、`repo` | 主键、所有者、范围 |
| `content` | 一条规则，最多 240 字 |
| `description` | 一句话摘要，最多 80 字，用于列表和将来的索引 |
| `status` | `active` 或 `archived` |
| `origin` | `agent` 或 `manual`；用户编辑过的改为 `manual` |
| `source_job_ids` | 来源任务，手动添加时为空 |
| `superseded_by` | 被哪条新记忆替代（归档时填写） |
| `created_at`、`updated_at`、`last_used_at` | 创建、修改、最近一次交给 Agent 的时间 |

- 开关按"用户一个、每个仓库一个"存放（`agent_memory_settings`）。关闭后该范围不记录新记忆，也不交给 Agent，已有记忆保留。
- 每个范围最多 30 条生效记忆。已满时，把最久没被使用的 Agent 记忆归档来腾位置，手动添加的不会被自动归档。全是手动添加时，新记忆不写入，设置页提示。

| 动作 | 结果 |
| --- | --- |
| 用户删除一条 | 立即物理删除 |
| 用户"清除"某个范围 | 删除该范围全部记忆，包括归档 |
| 删掉来源对话 | Agent 记下的记忆在来源全部被删后一起删除；手动添加的保留 |
| 被替代或因上限淘汰 | 归档，90 天后物理删除 |
| 撤销一次写入 | 删除这次写入；它替代过旧记忆的话，旧的恢复生效 |

## 记忆从哪里来

| 来源 | 方式 | 范围 |
| --- | --- | --- |
| Agent 记下 | 任务中调用 memory 工具：用户说"记住…"、纠正 Agent、表达稳定的偏好，或 Agent 发现值得长期遵守的规则 | 默认当前仓库；用户明确说"所有项目"时写用户级 |
| 手动添加 | 设置页 | 用户选择 |

memory 工具由 MCP 中继内置提供。五个运行时都接入了平台 MCP，实现一次即可。有三个操作：`memory_save`、`memory_update`、`memory_delete`。没有读取操作，因为记忆在会话开始时已交给 Agent。

- 归属（用户、仓库、任务）由控制面从任务的 MCP 令牌查出，不接受 Agent 自报，沙箱里的代码写不到别人或别的仓库名下。没有仓库的对话只能写用户级。记忆开关关闭的范围不接受写入。
- 系统提示说明该记什么（用户明确要求的、纠正、稳定的偏好），不该记什么（一次性要求、能从代码或 `AGENTS.md` 看出的内容、凭据）。
- 不需要额外的模型调用。Agent 自己记，也看得到完整上下文。代价是记不记取决于 Agent，不同模型的积极程度不同。

Agent 记下的记忆统一写成一句英文，命令、路径、名称保持原样。这样 Agent 读到的记忆一致，不同语言说的同一条规则也能去重。用户手写的记忆按原文保存。

## 写入时整理

| 结果 | 条件 | Agent 怎么做 |
| --- | --- | --- |
| 新增 | 没有意思相同的记忆 | `memory_save` |
| 合并 | 与已有记忆相同或是其补充 | `memory_update` 那条 |
| 替代 | 与已有记忆矛盾 | `memory_update` 那条，写成新规则 |
| 忽略 | 已被覆盖 | 不调用 |

服务端护栏：

- 与同范围生效记忆文字相同（忽略大小写和句末标点）的新增，直接返回已有那条，只追加来源任务。
- `memory_update` 不覆盖原记录：写入新记忆，旧的归档并记下 `superseded_by`。`memory_delete` 也只归档。所以每次改动都能在设置页恢复。
- Agent 可以改或删它看得到的任何记忆，包括用户手写的。Claude Code 的自动记忆也是如此，这里多了归档和恢复这层保护。
- Agent 只能看到和改动当前仓库与用户级的记忆。
- 凭据检查、240 字上限和"只对本次任务有效"检查与手动添加相同，不通过就拒绝并把原因返回给 Agent。

## 交给 Agent

控制面把记忆拼进请求，只在会话第一轮和记忆变化后发送。沙箱使用原生会话续接，上一轮的内容还在上下文里，每轮重发会重复出现。

1. 第一轮发完整记忆：先当前仓库的项目记忆，再用户记忆，合计不超过 12000 字。每条带 id，供 memory 工具修改和删除。没有记忆时什么都不加。
2. 之后只有记忆自上次发送后变化时，才发一段"记忆已更新"，写明新增、修改和废弃的条目。
3. 超过上限时按"项目优先、最近确认或使用过的优先"取舍。
4. 实际发送的记忆记入该轮任务，并更新 `last_used_at`。

措辞称其为"用户的长期偏好"。Agent 自动记下的没有经用户确认，所以注明"自动整理，可能过时，与当前请求冲突时以当前请求为准"。

尚未实现的扩展：对 Claude Code 和 Codex，把记忆导出为用户级指令文件（`~/.claude/CLAUDE.md`、`$CODEX_HOME/AGENTS.md`），让 Agent 当作原生指令；条数变多后改发索引（用 `description`），需要时再取全文。数据以数据库为准，文件只是副本。pi、OpenCode、Kilo 是否支持用户级指令文件还没核实。

## 用户界面

**设置页"记忆"卡片**（"用户记忆 | 项目记忆"切换）：顶部有开关、"添加"、"清除"。已保存的记忆每条一行，标出来源和最近使用时间，可编辑、删除。折叠的"已归档"区放被替代或被淘汰的旧记忆，可恢复。

**计划但未实现的对话内界面**：每轮开头显示"用了 3 条记忆"，点开可看条目并停用某条；用户消息旁有"记住这条"，把原文存成手动记忆（超过 240 字时请用户精简）；Agent 调用 memory 工具处显示一行灰色小字"已记住：… · 撤销"（更新时显示"旧 → 新"，写到用户级时注明"所有项目"）。

## 安全

记忆会进入以后每一次任务，最大的风险是别人的文字混进记忆，长期影响 Agent。

| 风险 | 对策 |
| --- | --- |
| 仓库文件、网页、工具输出或粘贴内容里的"记住：…"诱导 Agent 写入（提示注入） | 这是自动记忆的主要风险，Claude Code 同样存在。默认只写当前仓库，影响不到别的项目；系统提示要求只记用户本人的要求；所有写入都归档可恢复 |
| 沙箱里的代码冒充 Agent 或写到别人名下 | 归属只从任务的 MCP 令牌查出，任务结束后令牌失效 |
| 密钥、令牌被记下 | 写入前用凭据检查（`normalize_memory`，见 `cloud_agent/memory/agent_memory.py`），命中即拒绝 |
| 一次性指令变成长期规则 | 沿用临时范围检查，系统提示也要求不记 |
| 项目记忆串到别的仓库 | 按 `(user_id, repo)` 隔离，只发当前任务仓库的项目记忆，工具只能写当前仓库 |
| 记错而长期影响 Agent | 更新时旧的归档可恢复，长期不用的会被淘汰，措辞注明以当前请求为准 |

记忆只存在本服务的 Postgres，每次修改带版本号防止并发覆盖，不发给网关以外的服务。
