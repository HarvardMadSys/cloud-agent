# Agent 统一公网出口

状态：已实现。所有任务使用同一套沙盒网络；目标环境的 Kata 验收仍是发布条件。

相关：[AGENTS.md](../../../AGENTS.md) §7（网络规则摘要）、[沙盒安全模型](2026-09-01-agent-sandbox-security-model.zh.md)。规则由 `cloud_agent_shared/egress.py` 渲染，由 `cloud_agent_host/network/network_guard.py` 安装并回读校验。

## 1. 目标

准备环境、安装依赖和 Agent 执行共用一套网络，能访问公网，以运行 curl、Python HTTP 客户端、pip、npm 和 Git over HTTPS。Fork 沿用同一组的网络与工作区。

没有网络模式、档位、域名白名单或代理，用户和运维都不能选择或放宽。网络保护未就绪时拒绝执行任务。运行中发现保护失效时，停止执行并断开该组网络，保留工作区。这是故障处理，不是另一种可运行的网络。

## 2. 固定边界

沙盒组只能到达：

| 类别 | 规则 |
|---|---|
| 公网 | 普通公网 IPv4 单播地址的 TCP 80/443 |
| DNS | `AGENT_EGRESS_DNS_SERVER` 指定的一个解析器，TCP/UDP 53 |
| 本组中继 | 本组网桥上的 MCP 中继（只开放 MCP 专用应用的工具入口）。主机配置了的话，还有模型中继和 GitHub 中继的隧道；`git` 和 `gh` 通过它以 `github.com`、`api.github.com` 的 443 端口访问 GitHub |
| SSH 服务器 | owner 登记、验证并为本组某个聊天启用的每台 SSH 服务器，限定其公网 IPv4 地址和端口 |

其余全部拒绝：宿主的所有地址；私网、链路本地与云元数据、CGNAT、组播、保留地址；`AGENT_EGRESS_PROTECTED_CIDRS` 追加的网段；其他沙盒组；其他端口、UDP 443、IPv6；外部主动入站。回包只接受获准出站连接的。

中继是固定目的地的转发器，调用方不能指定上游，也不是通用 HTTP 代理。公网访问不经过任何代理，由宿主规则按实际数据包判断，不依赖 Agent 自觉，也不依赖客户端类型。

已接受的限制：

- TCP 80/443 只是端口约束，不检查内容，不承诺阻止 DoH 或这些端口上的隧道。
- 不防外发。沙盒可以把仓库内容和短期令牌发往公网。
- 平台的公网地址可能可达。MCP 工具路径不在主 API 上，推理 grant 的重放风险按 §3 接受。

## 3. 入口隔离与已接受的推理 grant 风险

MCP 工具调用只由 MCP 专用应用提供。中继最终连到该应用（容器内默认 8001），不是主 API。主 API 保留连接管理、OAuth 回调和工具审批，不挂载工具调用路由。

推理 grant 仍由网关签发，进入成员的 CLI 进程环境或私有临时配置。推理中继连到网关现有的推理入口。项目接受以下风险，不要求独立内部入口：

- 仓库、依赖或网页内容可能促使任务代码取得并外传本成员的 grant。持有者可通过可达的网关推理入口重放它。
- 重放仍归属 grant 对应的用户，只能调用其被允许的模型，受该用户的配额、有效期和撤销检查约束。它消耗用户额度和平台推理资源，没有固定的损失上限，也不授予其他用户身份、MCP 工具或平台管理权限。
- grant 的短 TTL 不是从泄露时起算的固定窗口。驻留进程存活期间心跳会续期，turn 结束不撤销 residency grant，30 分钟空闲回收也不是绝对上限。停止、替换、接管和释放时照常撤销，撤销失败由剩余 TTL 兜底。

成员凭据隔离、平台长期密钥不进沙盒、模型权限和配额检查、租约与撤销，都不因此放宽。

Owner 主动配置的个人环境凭据是单独的产品输入，允许进入其沙盒，并接受经公网出口外发、进入模型上下文或被代码写入文件的风险，见[环境设计](2026-10-12-repository-environment-design.zh-CN.md) §9–§10。它不增加出口，不允许覆盖平台凭据名。

## 4. 拓扑与配置

```text
沙盒组（准备、执行、Fork 共用）
  └─ 本组网桥
       ├─ 推理/模型中继 ──> 网关推理入口
       ├─ MCP 中继 ──> MCP 专用应用
       └─ 宿主防火墙、路由与 NAT ──> 公网 IPv4 TCP 80/443
```

每个沙盒组一张可路由的 Docker 网桥，从本部署的地址池分配 /29，接口名带本部署前缀。桥上只有该组容器和受信中继。网络按组及 generation 归属管理，stop 时移除网桥，wake 时重建，sandbox manager 对账时清理带标签的孤儿网桥（五分钟宽限，避免与正在进行的挂接竞争）。

中继在 `AGENT_RELAY_NETWORK`（`internal`）上被发现，再按别名挂到各组网桥，以网关优先级 -1 加入，所以组网桥不会成为中继的默认出口（需要 Docker 28 及以上，预检会拒绝旧版本）。沙盒不加入该网络。

公开多租户执行仍要求 Kata、非 root、移除 capabilities、seccomp 和资源限制。runc 只用于受信仓库。

| 参数 | 用途 |
|---|---|
| `AGENT_SANDBOX_NAMESPACE` | 本部署资源和防火墙表的归属标识 |
| `AGENT_EGRESS_CHAT_NETWORK_POOL` | 组网桥的 IPv4 地址池（RFC1918），显式配置 |
| `AGENT_EGRESS_DNS_SERVER` | 一个固定的 IPv4 解析器，只授权 TCP/UDP 53 |
| `AGENT_EGRESS_PROTECTED_CIDRS` | 追加的受保护网段，例如使用公网地址的实验室内网。只能增加保护 |
| `AGENT_RELAY_NETWORK` | 中继发现网络 |
| `AGENT_SANDBOX_MCP_URL`、`AGENT_SANDBOX_MODEL_RELAY_URL`、`AGENT_SANDBOX_GITHUB_RELAY_CA_FILE` | 固定服务的连接目标。未配置的中继，对应能力为空；请求被拒绝，不回退到网关 |

同一宿主上两个部署的地址池不得重叠，也不得与宿主已有路由（机房网段、VPN、私有服务）重叠，默认路由和宽于 /8 的兜底路由除外。检查的是完整地址池，不只是已分配的 /29。原因是 Docker 不检查显式子网与宿主路由的冲突，组网桥会把宿主发往这些地址的流量引入沙盒。

## 5. 宿主规则

规则是本部署自己的 nftables 表 `cloud_agent_<前缀>`，含 `inet` 和 `bridge` 两个 family。`inet` 管路由流量（公网、宿主、其他网桥），`bridge` 管同一网桥上沙盒与中继之间的帧。表内的 drop 不会被 Docker 自己的 accept 规则撤销。

runner 与 sandbox manager 不持有 `NET_ADMIN`。规则由短时 helper 安装：同一镜像，宿主网络命名空间，runc，只加 `NET_ADMIN`，只读根文件系统。沙盒不获得 `NET_ADMIN`、Docker socket 或其他特权通道。

要点：

1. 只作用于本部署的表和网桥接口。禁止全局 flush、修改他人规则或切换 Docker 防火墙后端。IPv6 按接口归属拦截。
2. 宿主所有本机地址不可访问。DNS 服务在宿主上时，只放行其精确地址和 53 端口。DNS 例外先于受保护网段判断。
3. 转发检查实际目的地址，Docker 端口映射也按 DNAT 后的真实目的地址检查。
4. 中继按（网桥、地址、端口）精确放行本组的，一个组的例外不能变成访问其他组。SSH 例外存在 `ssh_targets` 集合中，按网桥分别维护，晚于受保护网段判断，所以受保护空间里的地址即使被登记也仍被拒绝。每个包都检查，删除一个元素会切断已建立的 SSH 连接。
5. 更新保护集合或停用组网络必须约束已有连接，不被无条件的 `ct state established accept` 绕过。
6. 先安装并回读校验规则，再创建组网桥；校验失败时 runner 不接活。组网络操作复用 60 秒内的校验结果。runner 退出不删规则，宿主重启后规则重装前不启动任何组。
7. 有组在运行时，sandbox manager 至多每分钟回读一次规则并补装缺失部分。连续两次仍无法证明规则时，停止本部署所有运行中的组（保留工作区和 native session），规则恢复前不再唤醒。

## 6. DNS 与任务顺序

runc 容器以 `--dns AGENT_EGRESS_DNS_SERVER` 创建。Kata guest 的 `/etc/resolv.conf` 和中继的 `/etc/hosts` 条目由受信 guest-root helper 写入。helper 用平台固定的代码，仓库不能提供待执行命令或写入路径。

1. 宿主完成规则安装、地址池校验和运行时验证后才接任务。
2. 创建组网桥，挂接中继，写入 DNS，启动沙盒。
3. 每次冷启动后，在 guest 内以沙盒用户自检：默认路由、解析器配置、实际解析一次（根域 NS，3 秒内应答）、中继的 TCP 端口，以及两个边界探针：宿主（UDP）和元数据地址（TCP）必须被本部署规则以 ICMP "管理禁止"立即拒绝。宿主自己回"端口不可达"或无应答，说明流量没有经过规则。公网可达性不是启动条件。
4. 全部通过后才执行仓库代码或安装脚本。失败则停止沙盒、保留工作区，本 turn 失败。
5. 准备完成后直接执行 Agent，沿用同一网桥，没有网络阶段切换，没有 Kata guest 重启。
6. 沙盒恢复、中继替换、Docker 或宿主重启后重新核验边界。组释放时先移除本组连接和集合，再清理网桥。

## 7. 不存在的东西

旧的 `platform_only`、`trusted`、`custom`、`full` 档位，按阶段选择 tier，域名白名单，Squid 出口代理，`HTTP_PROXY` 类变量注入，以及 setup 与 agent 两阶段网桥切换已全部删除，不提供旧变量别名或 fallback。旧拓扑遗留的容器和网桥不被采用，只报告需要一次性清理。

## 8. 失败行为

规则缺失或校验失败，则停止执行并断开对应组网络，不退回无约束直连。能安全返回明确拒绝的连接立即报错。日志记录组、失败环节和原因，不记录令牌或请求正文。

## 9. 验收

完整安全验收在独立的 Kata 环境中进行，使用正在监听的受控目标，并以允许路径作正向对照。普通 Docker 的结果不能替代 Kata 证据。

| 类别 | 通过标准 |
|---|---|
| 公网能力 | curl、Python HTTPS 证书校验、HTTP 80、包下载、Git HTTPS 可用 |
| 端口与 DNS | 其他公网 TCP 端口、UDP 443、其他解析器的 53 被拒，指定解析器正常 |
| 地址分类 | 私网、链路本地与元数据、CGNAT、组播、保留地址、追加保护网段被拒；DNS 重绑定或重定向后的私网连接也被拒 |
| 宿主与映射 | 宿主各类地址上的监听服务、网桥网关、Docker 发布端口都不能绕过保护 |
| 组与部署隔离 | 另一组的监听服务不可达；冲突地址池被拒；两个部署并行不会改动或误伤彼此规则 |
| 中继 | 本组中继的服务端口可用，其他端口被拒；替换中继后例外及时更新 |
| IPv6 与入站 | IPv6 被拒；外部不能主动连入；获准出站连接的回包正常 |
| 不可信代码权限 | 成员不能修改路由、防火墙、受管 DNS 或宿主规则，也不能取得 helper 权限 |
| 执行顺序 | 规则、DNS 和自检完成前不执行仓库代码；准备到执行沿用同一网桥 |
| 生命周期 | 恢复、中继替换、Docker 或宿主重启后边界不变；故障时停止执行、断开出口、保留工作区；组释放无残留 |
| 已有连接 | 改为受保护目标或停止组网络后，持续收发的连接确实停止，未受影响的对照继续通信 |
| 凭据入口 | MCP 令牌在主 API 找不到工具路径；推理 grant 的用户绑定、模型权限、配额、有效期和撤销检查保留。推理 grant 的公网重放按 §3 接受，不作为必须拒绝的断言 |

拒绝项必须有可达的受控目标作对照，使用随机测试数据，不发送仓库文件或真实凭据。用有意移除一条限制的方式证明测试能发现放行漏洞。超时、目标未监听或证据不足不得记为阻断成功。

## 10. 不在范围

用户或运维可选的网络模式、域名白名单产品、每组网关容器、网络租约、策略快照、逐连接出站审计、滥用监控、IPv6 出口、浏览器服务和公网预览都不实现。宿主规则上的拒绝计数是本部署的总量，不归属到组或成员。
