# CloudLab 节点自动轮换与整机迁移

状态：已实现（轮换流程与管理界面）。手动跨站点的真实会话演练已通过。自动流程的 staging 验收和连续两周的无人值守验收尚未完成。

本文是 [计算资源生命周期设计](2026-10-04-compute-resource-lifecycle-design.zh-CN.md) 中跨机器迁移的一个用例，只覆盖 CloudLab 节点到期。

## 目标

CloudLab 节点到期或续期被拒时，系统自动换一台新节点，把沙箱整机搬过去。会话不丢，用户基本无感，不需要人盯着。

## 约束

CloudLab 侧：

- 实验必然到期，到期后本地盘被清空，无法恢复。短续期自动批准，长续期要工作人员审批。
- 续期可能被其他项目的预留挡住，新建也可能失败。实验变成 `failed` 不一定是没有空闲机器，Portal API 不返回失败原因。
- API 把 `bindings` 的值存成字符串，收到 JSON 布尔值会返回 400。
- API 所在主机偶尔返回已过期的证书，导致 TLS 握手失败。
- 已认证 API 返回的 manifest 不含节点的 SSH 主机公钥。
- API 可以创建和更新 profile，profile 可设为仅项目成员可见。

平台侧：

- 沙箱的工作区和原生会话只在容器可写层里。空闲时 `docker stop`，下次使用时 `docker start`，在同一容器里恢复。系统没有按聊天记录重建会话的路径。
- 保留的沙箱固定在一个主机名上，后续回合只派给这个主机名。主机暂停或离线时，用户消息照常排队，没有超时。
- 单个回合有硬上限 `AGENT_TIMEOUT_S`（默认 3600 秒，可在管理页调整）。
- 主机名由节点生成，代码拒绝把已有主机名绑定到另一台节点。节点上还有保留沙箱时不能释放。
- 同名重新登记会作废这个名字原来的凭据，并把主机状态重置为"登记中"，管理员设置的暂停随之解除。所以换节点期间必须用独立的 `rotation` 准入限制，不能复用管理员的暂停。

## 方案：整机搬家

节点会换，沙箱状态有两种保存办法：

- 跟着机器走（采用）：每次换节点，把整台机器的 Docker 数据拷到新节点。会话机制不用改，不需要外部存储。
- 存到节点外：沙箱停下后导出到持久存储，使用时在当前节点恢复。CloudLab 自带的持久存储只能在站点内用，有配额且慢；放到 CloudLab 之外则要跨公网拉数据，还有合规问题。以后可作为节点突发故障时的备份手段。

## 节点生命周期

- 到期前先尝试续期，只申请会自动批准的短续期。提前量由续期策略配置，建议 3 小时。
- 续期被拒，或节点已用满 `max_node_age_seconds`（默认 7 天），开始换节点。
- 第一次失败告警；到期前 1 小时仍未完成，再告警一次。

## 选新节点

候选机型由管理员配置（`node_types`），按 CloudLab 硬件表的上线年份（`Circa` 列）从新到旧排列。只放 x86、无 GPU、无需单独审批、有 SSD 或 NVMe 的机型。

| 现象 | 归类 | 处理 |
| --- | --- | --- |
| 创建请求返回 4xx | 配置错误 | 停止并告警 |
| 返回 401 或 403 | 凭据问题 | 停止并告警 |
| 实验几分钟内变成 `failed`，且没有分到机器 | 可能没有空闲 | 释放，换下一个机型 |
| 分到机器后变成 `failed` | 装机或启动失败 | 释放、告警，换下一个机型 |
| 同一种失败连续出现在三种机型上 | 系统性问题 | 停止并告警，不再试剩余机型 |

每次失败都把现象、机型和时间记入操作结果。创建失败的实验由申请操作自己释放，它从没运行过主机，不走释放保护。

## 新节点登记主机公钥

控制面第一次 SSH 到新节点前，必须已可靠地知道它的主机公钥。信任来源是一个受保护的一次性登记凭据，不是实验名称或 UUID。

1. 开节点时，控制面生成随机的一次性凭据，只存哈希。凭据绑定这次分配，有有效期（默认 2 小时），只能用来登记主机公钥，不能领任务，也不能接管主机名。
2. 凭据作为 profile 参数（`registrationToken`，登记地址为 `registrationUrl`）交给 CloudLab，只出现在发出的创建请求里，不写入本地配置或日志。
3. 节点用我们自己的 profile 开机，开机脚本校验控制面的 TLS 证书，把本机的 SSH 主机公钥提交上来。
4. 控制面校验哈希、有效期和状态，记下公钥，把凭据标为已用。同一凭据重试得到同样的结果，换另一把公钥会被拒绝。
5. 申请操作等登记完成，把公钥固定到节点记录。之后的 SSH 连接只认这把公钥，严格校验。

profile 参数对 CloudLab 项目成员可见。成员本来就能以 root 登录项目内所有节点，所以信任范围没有扩大。凭据不出现在网址、邮件和控制面日志里，用过或过期即作废。

登记只说明"这台机器归我们管"。接管旧主机名、作废旧凭据发生在切换步骤里。

登记接口在控制面的公开 API 上，是新的公开入口：只接受固定格式的小请求，凭据不对时统一返回同一种错误，每次登记都写审计。

## 数据模型

| 位置 | 字段或表 | 含义 |
| --- | --- | --- |
| `agent_compute_allocations` | `slot_host` | 本分配的节点以哪个主机名上线；为空沿用 `compute-<节点 ID>` |
| `agent_compute_allocations` | `slot_namespace` | 沙箱命名空间（Compose 项目名）；为空沿用 `ca-<节点 ID>` |
| `agent_compute_allocations` | `predecessor_id` | 被本分配替换的旧分配 |
| `agent_compute_nodes.connection` | `host_key` | 登记后固定的主机公钥 |
| `agent_compute_node_registrations` | 表 | 登记凭据的哈希、有效期、状态、登记的公钥 |
| `agent_host_admission_holds.purpose` | `rotation` | 换节点期间暂停领取任务 |

- 新分配继承旧分配当前使用的主机名和命名空间。容器标签、网桥和 nftables 表名都从命名空间派生，必须保持不变。
- 主机交接在独占锁内把主机记录的 `compute_node_id` 从旧节点改到新节点，去掉旧分配对这台主机的其他限制，`rotation` 限制随主机迁过去。之后旧节点上没有绑定的主机，可按原规则释放。
- 每个位子至少准备两套部署配置（各自的隧道授权和反向端口），新旧节点轮流使用。

## 换节点流程

旧节点 A，新节点 B。

| 步骤 | 做什么 | 失败时 |
| --- | --- | --- |
| 选择节点 | 按机型列表选，选一套空闲的部署配置，创建 B（继承主机名和命名空间） | 没有空闲配置：停止并告警 |
| 等待节点 | 等 B 开出来、完成登记、装好 Docker 和 Kata、上传部署包。B 不登记主机、不启动服务 | 按上节处理 |
| 预拷贝 | A 照常服务，把 Docker 数据预拷到 B | 重试；多次失败则释放 B，换机型 |
| 等待空闲 | 等到没有回合在运行，立即暂停领取并再确认一次 | 到排空截止时间仍不空闲，则主动排空：暂停领取，等运行中的回合结束 |
| 停止旧节点 | 停 A 上的主机服务和 Docker | 回退 |
| 补拷 | 拷贝最后的变化 | 回退 |
| 主机交接 | 数据库里把主机名交给 B 的节点 | 回退 |
| 启动新节点 | 签发登记令牌，在 B 上启动主机服务，以原主机名重新登记，A 的旧凭据随之作废 | 回退 |
| 确认 | 主机在线，心跳晚于令牌签发时间，sandbox manager 健康，然后恢复领取 | 回退 |
| 清理 | 删除 A 上的副本，释放 A | 重试，不影响用户 |

排空截止时间 = 到期时间 − `AGENT_TIMEOUT_S` − 切换时间（约 10 分钟）− 余量（约 30 分钟）。默认配置下约在到期前 1 小时 40 分。此时新节点仍在准备，也要先让旧主机停止领取新任务，给运行中的回合留出时间。上限调得太大、提前量容不下时，提前告警并提示调大提前量。接近到期仍有回合运行时升级告警，不强制杀回合。

回退：先确认 B 上的服务已停，再把主机名交回 A，必要时让 A 重新登记，启动 A，确认在线后恢复领取，然后释放 B，换下一个机型重试。无法确认 B 已停时保持暂停并告警，不能同时启动两份主机。A 上的数据在 B 确认之前不删除。

恢复边界：

- 停 A 之前先记下停止意图，避免部分停止后误以为 A 仍正常。
- B 的验证结果先持久化，再解除暂停。解除之后 B 会产生新数据，只能清理 A，不能回退到旧副本。清理失败保留检查点重试。
- 备用部署配置必须与 A 的代码版本和部署包摘要一致。

用户感知：排空和切换期间发出的消息显示"等待开始"，恢复后自动执行；切换后的第一条消息需要冷启动，和闲置后再使用一样；运行中的回合不会被打断。

## 数据拷贝

- 只拷 `/var/lib/docker` 和 `/var/lib/containerd`。状态目录不拷，凭据由重新登记生成；Kata 纪元不拷，B 自己生成，只触发一次运行时重新验证。
- A 直接推送到 B：`rsync -aHAXSx --numeric-ids`，停机后的最后一遍加 `--delete`。A 用一把只在本次换节点期间加入 B 授权列表的临时密钥，并用 B 已登记的主机公钥严格校验 B。
- 必须带 `-x`。Docker 使用 containerd 镜像存储时，运行中容器的合并文件系统挂在 `/var/lib/docker/rootfs/overlayfs/<容器 ID>`，不带 `-x` 会把每个运行中容器的完整文件系统当普通文件再拷一遍。
- 分多路并行，快照目录、镜像内容（content blobs）和其余文件分开拆，不留单路大头。跨站点单路只有约 30 MB/s。停机后的最后一遍也分路。
- 停 A 时先停 runner，再单独停 Sandbox Manager（最多等 10 分钟）：它退出时会逐个停掉还开着的沙箱，开启生命周期归档时还会上传 final。之后并行停剩下的容器。被 Docker 绕过 Sandbox Manager 停掉的沙箱，这次不存 final 归档，会话照常继续。
- 两台节点的 Docker 和 containerd 数据都放在实验的本地大盘上，用 bind mount 挂到默认路径。
- B 与 A 部署版本相同时，镜像和构建缓存随数据过来，启动时不需要重建。

## 告警与管理界面

告警复用 `AGENT_ALERT_WEBHOOK_URL`，内容只含事件名、主机名和原因代码；未配置时只写结构化日志。

管理页的服务器行显示当前节点、到期时间、下次换节点时间和上一次结果。续期策略面板可设置是否自动换节点、节点最长使用时间和候选机型。**立即换节点** 用于验收和紧急情况。服务器上有需要处理的失败时显示"需要处理"。

## 验收

手动演练（staging）：把 Clemson 节点 A 接入为临时主机，建 Claude Code 会话、它的 Fork 和 Codex 会话，再整机搬到 Utah 节点 B，B 用同一主机名和命名空间重新登记。三个会话在 B 上都从原生会话恢复，上下文、文件和容器 ID 不变，Fork 与原会话的上下文仍然分开。主机不可用共 161 秒。

待完成的 staging 验收：强制换一次节点；跨站点换一次；故障演练（续期被拒、首选机型开不出来、切换中途失败后回退、控制面在换节点中途重启）；连续两周无人值守且至少自动换两次。生产使用前，经项目负责人向 CloudLab 报备一次。

## 风险

- 节点突然故障（不是正常到期）时来不及搬，该节点上的会话会丢失。
- 续期被拒且所有候选机型长时间开不出来时，会话会丢失。
- 目前依赖个人的 CloudLab token。
